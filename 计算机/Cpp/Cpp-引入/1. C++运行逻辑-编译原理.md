## C++运行逻辑-编译原理

###  概念

```ad-note
title: 申明
告诉编译器 函数存在

<font color="#2DC26B">只需要包含函数声明即可</font>
```
```cpp title:例子
void Log(const char* message);
```

```ad-note
title: 定义
告诉编译器 函数到底是什么

<font color="#2DC26B">需要包含函数整体</font>
```
```cpp title:例子
void Log(const char* message)
{
    std::cout << message << std::endl;
}
```

```cpp title:'预处理'
#include <iostream> 
//只是将所有内容复制到引入的地方

#if 1
//if后面为1即True 中间部分内容才会在预处理过程中被引入

```
###  编译阶段
```ad-note
title: 编译Build
将源代码转换为机器代码或汇编代码的过程。
在这个阶段，编译器会对每个源文件进行词法分析、语法分析、语义分析、优化和代码生成。
通过这些步骤，编译器会检查代码中的语法错误和语义错误，并将代码转换为目标文件（*.obj*）
这些目标文件通常包含机器码和一些符号信息，但还不能直接运行。

```

###  链接阶段

```ad-note
title: 链接Link
链接阶段是将一个或多个目标文件和库文件链接在一起
生成可执行文件（Executable File）的过程
在这个阶段，链接器会解决符号引用，将各个目标文件中定义的函数和变量链接起来，并且处理库文件的引用
链接器还会进行一些优化，比如消除未使用的代码和数据，从而生成最终的可执行文件

```

```cpp title:入口函数
int main(){
//main为默认入口函数 在Link的属性面板可以自定义别的入口函数
}
```
### 报错分析

> [!bug] 分析
> Visual Studio 编译运行报错
> - 以 Cxxxx 的报错，即发生在 Compile 编译阶段
> - 以 LNKxxxx 的报错，即发生在 Linking 链接阶段
> - 未解决的外部符号 unresolved external symbol
> 	- 声明的函数（声明即认为存在）在链接阶段没有找到对应的函数体
> 	- 如果函数有具体的定义的函数体，但在入口函数 main 中并没有调用，此时在 LNK 阶段也会报错（这样设计的初衷是，这个函数还可能在别的地方调用）
> 		- 处理办法：用 **static** 表示只会在本文件中调用
> 	- 声明和定义的类型不一致如 void 和 int
> 	- 声明为一个，而定义中函数入口参数的数量不对应（调用函数的问题）
> - 定义中函数的一样函数名的函数有多个，编译器不知道应该调用哪个函数
> 	- *（此处与函数重载区分开）*
> 	- 办法：
> 		- 使用.h 宏文件定义函数配合 static （使在 cpp 中调用的每次一函数都为内部函数，即不同函数）
> 		- 使用.h 宏文件定义函数配合 inline （将函数体替换原本调用的位置，传入的参数也替换）
